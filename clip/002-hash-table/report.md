# 報告：002-hash-table

## メモとの食い違い・誤りの指摘
- **誤り**：メモの「ハッシュ関数が優秀なら、異なるキーが同じ箱に当たる『衝突』は絶対に起きない。だから常に 1 回で見つかる」は誤り。
  - 取りうるキーの種類は箱の数より多いので、どんなハッシュ関数でも衝突は避けられない（鳩の巣原理。CLRS 11.2）。良いハッシュ関数は衝突を減らせるが、なくせない。
  - 速いのは「平均して」一定時間であって「常に 1 回」ではない。衝突したキーは同じ箱の中を順に見る。最悪の場合は遅くなる（Java HashMap のドキュメントも「ハッシュ関数が要素をうまく散らすことを前提に」一定時間としている）。
  - 台本は正しい内容で作った：「衝突は避けられない → 同じ箱につなぐ → 混んだら箱を増やして入れ直す → 平均してほぼ一定」。
- その他の項目（配列の直接アクセス、ハッシュ関数で番号に変える、平均一定時間、リハッシュ）は正しい。
- 注：メモは Claude が作った仮のもの（`memo.md` 冒頭に明記）。

## 動画で単純化した点
- 「apple → 3」「lemon → 3」は説明用の例。実際のハッシュ値ではない。画面に「※ 番号は説明用の例」と表示している。
- 衝突の解決はチェイン法（同じ箱につなぐ）だけ見せた。Python の dict などが使うオープンアドレス法には触れていない。
- 「ほぼ一定の時間」は平均の話。台詞と画面の両方で「平均して」と出している。最悪計算量には触れていない。
- リハッシュは「混んだら箱を増やして入れ直す」の一言だけ。負荷率やしきい値（Java の既定は 0.75）には触れていない。
- 箱は 7 個の模式図。
