# 台本

## Hook
何万件のデータから、1件をほぼ一発で取り出す。どうやっているんでしょう？
> 映像: タイトル「ハッシュテーブルはなぜ速い？」。縦に並んだ 7 つの箱（0〜6 番）が現れる。

## Setup
配列なら、番号さえ分かれば、その箱に直接行けます。3番なら、3番を見るだけ。
> 映像: 右上に「3」。3 から 3 番の箱へ矢印が伸び、3 番の箱だけが光る。

## Core
でも、探したいのは、appleのような文字列です。そこで、ハッシュ関数で、キーを番号に変えます。
> 映像: 上の段に「apple → [ハッシュ関数] → 3」の流れが左から順に現れる。
appleが3になったら、3番の箱に入れます。
> 映像: apple が 3 番の箱へ移動して収まる。
探すときも、同じ計算で、3番の箱を見るだけ。件数が増えても、手間はほぼ同じです。
> 映像: もう一度 apple（探す側）が関数を通り、3 番の箱が緑に光る。「計算 1 回＋箱を見る」の表示。
ただし箱の数には限りがあり、別のキーが同じ番号になる「衝突」は避けられません。
> 映像: lemon が関数を通り、同じ 3 が出る。3 番の箱が赤く光り「衝突」。
そのときは、同じ箱につなぎます。混んだら箱を増やして入れ直すので、列は短いままです。
> 映像: lemon が 3 番の箱の横に移動し、apple とつながる。下に「混んだら 箱を増やして入れ直す」。

## Payoff
キーから、置き場所を計算する。だから、平均して、ほぼ一定の時間で見つかるんです。
> 映像: key → 関数 → 箱 の道筋がまとめて光り、強調語が出る。最終状態で静止。
