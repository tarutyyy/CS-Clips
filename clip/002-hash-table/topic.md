# ハッシュテーブルはなぜ速い？
## 伝えたい一点
ハッシュテーブルは、キーから置き場所（箱の番号）を計算して直接その箱を見るので、件数が増えても平均してほぼ一定の時間で見つかる。

## 想定視聴者・前提知識
配列を使ったことがあるプログラマ。添字で要素に直接アクセスできることは知っている。

## 使いたい見せ方のアイデア
- 縦に並んだ箱（0〜6 番）。「3 番」と言われたら 3 番の箱だけが光る（配列の直接アクセス）
- 上の段で `apple → [ハッシュ関数] → 3` と流れ、apple が 3 番の箱に入る
- 探すときも同じ計算 → 3 番の箱だけが緑に光る
- 別のキー lemon も 3 になり、赤く「衝突」。lemon は 3 番の箱の横につながる（チェイン法）

## 触れないこと（スコープ外）
- 具体的なハッシュ関数の作り方、最悪計算量 O(n)、オープンアドレス法の詳細、ハッシュ攻撃
- リハッシュの手順そのもの（「混んだら箱を増やして入れ直す」と一言だけ触れる）

## 選ばなかった論点
- リハッシュ（負荷率としきい値、償却計算量）は別クリップ向き
- 衝突の解決法の比較（チェイン法とオープンアドレス法）

## Gate1 自己判定
- 伝えたい一点は 1 つ：はい（キーから置き場所を計算するので速い）
- 60 秒で伝えきれる大きさ：はい
- 動きで見せる価値：はい（キーが関数を通って番号になり、箱に入る流れは動きで見せると分かりやすい）
