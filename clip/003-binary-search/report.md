# 報告：003-binary-search

## メモとの食い違い・誤りの指摘
- なし。メモの各項目は正しい。
  - 「最悪 log2(n) 回くらい」：正確には ⌊log2 n⌋ + 1 回（Knuth §6.2.1）。「くらい」の範囲で正しい。
  - 「100万個でも20回ほど」：2^19 ≤ 100万 < 2^20 なので最悪 20 回。正しい。
  - 「連結リストには向かない」は正しいが、論点を 1 つに絞るため動画では扱わなかった（topic.md「選ばなかった論点」）。

## 動画で単純化した点
- 「比べる」1 回で「等しい／小さい／大きい」を判定する数え方（Knuth の Algorithm B と同じ）。
- 「半分」は厳密には「真ん中を除いた残りの半分」（15 → 7 → 3 → 1）。画面では箱を 1 つずつ正確に暗くしている。
- 「100万個でも20回ほど」は最悪の回数。平均はやや少ない。
- 15 個の配列と探す値 37 は説明用の例。37 は最悪の 4 回目に見つかる位置に置いた。
- 先頭から順に見る探索は 8 個目まで見せて止め、「100万個なら最悪100万回」の文字で補った。

## Gate3 自己判定
- 一度に動くものは 1 つ：おおむねはい。矢印の移動 → 箱が光る → 比較式 → 範囲が暗くなる、の順に起きる。mid の冒頭だけ、線形探索の片付け（暗い箱が戻る・回数が 0 に戻る・赤い説明が消える）が同時に起きる。リセットの 1 動作として扱った。
- 字幕を読む時間：各文 3.0〜8.1 秒。字幕は 2 行以内。
- セーフエリア内：はい（図は y 170〜1120 相当。下の説明行も字幕の上）。
- 音なしでも分かるか：「探す 37」、矢印、「37 > 30」などの比較式、暗くなる範囲、比べた回数のカウンタ、最後の「15個→4回／100万個→20回／200万個→21回 +1回」で筋が追える。
