# 台本

## Hook
1億行のテーブルから、1行を探す。どれくらいかかるでしょう？
> 映像: タイトルと、行が並んだ巨大なグリッド。カウンターは 0。

## Setup
インデックスがないと、先頭から順番に、全部の行を調べるしかありません。最悪、1億回です。
> 映像: 行を先頭から順に光らせる。カウンター「調べた行数」が 1億 に向かって回る。

## Core
そこで使うのが、インデックス。多くのデータベースでは、B+木という、木の形をしています。
> 映像: グリッドが縮み、同じ画面の中で木（根・内部・葉）に変形する。
1つのノードには、目印が数百個入っています。だから、枝がとても広がるんです。
> 映像: 根のノードを強調し、「数百個」のラベル。枝が大きく広がる。

## Payoff
根から葉へ、たどるのは、たったの3〜4段。目的の行まで、4回ページを読めば届きます。
> 映像: 根 → 内部 → 葉 と道筋だけが順に光る。カウンター「読んだページ数」が 4 で止まる。
1億行でも、10億行でも、ほとんど同じ。**インデックスは、探す範囲を一気に絞る**仕組みなんです。
> 映像: 全体が最終状態で静止し、強調語が出る。

## Gate2 自己判定
- 主張に出典あり：はい（research.md）
- 単純化しすぎて嘘になっていないか：段数を「3〜4」と幅で示し、全件走査は「最悪」と明示
- 最初の 3 秒で興味を引けるか：問いかけで始める
- 専門用語：インデックス、B+木、ノードの 3 つ（目安の 2 つをやや超える。仮メモのため許容）
- 60 秒に収まるか：はい（約 45 秒の見込み）
