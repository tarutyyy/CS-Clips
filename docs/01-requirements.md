# CS-Clip 要件定義書

> 文書体系：01 要件定義（何を・なぜ） → 02 仕様書（外から見た振る舞い・形式） → 03 設計書（内部構造・実装方針） → 04 契約書（factory と clip の境界）
> `【要決定 Qn】` は未決事項。決定したら本文に反映して印を消す。

## 1. 背景と目的
- **自分の学習メモを投入すると、その内容を図解で説明する約1分の動画（MP4）が自動でできあがるシステム**を作る
- 動画の強み（状態の変化・連続性）を活かし、静止画では伝わりにくい「動き」で理解させる
- 制作過程そのものを復習とする（説明できるかの確認）
- Claude Code を制作エンジンとし、人間は「メモを書く」と「できた動画を見る」に集中する
- 用途は YouTube Shorts を想定するが、本システムの責務は MP4 の出力まで（投稿・YouTube 連携は扱わない）

## 2. 利用者
| 役割 | 担当 | 責務 |
|---|---|---|
| オーナー | あなた | 学習メモの投入、できた動画の確認と修正指示（任意で途中レビュー） |
| 制作エンジン | Claude Code | メモの解釈と論点の抽出、裏取り調査、台本、ビート分割、映像実装、自己検証 |
| 視聴者 | CS を学ぶ学生・若手エンジニア（想定） | スマホで縦型・音声あり / なしで視聴 |

## 3. スコープ
| 項目 | 決定事項 |
|---|---|
| 分野 | アルゴリズム / OS / ネットワーク / DB / Web |
| 尺 | 約60秒（目安。60 秒を超えない） |
| 主張 | 1本につき「伝えたい一点」は1つだけ |
| 画面 | 1080×1920 縦型, 30fps |
| 見た目 | 3Blue1Brown 風：暗い背景・図解のみ・滑らかな変形。キャラクターは出さない |
| 言語 | 日本語のみ（英語版は将来、別チャンネル） |
| 音声 | VOICEVOX または AivisSpeech（切り替え可能） |
| 字幕 | 必須（無音視聴対策） |
| 入力 | 自分の学習メモ（Markdown） |
| 出力 | MP4 ファイル。投稿は手動で、システムの範囲外 |

## 4. ユーザーストーリー
- US0：オーナーとして、学習メモを置いてコマンドを 1 つ実行するだけで、1 分の解説動画がほしい。途中で何も操作しなくても最後まで進んでほしい。
- US1：オーナーとして、メモの内容が正しいか裏取りされ、誤りや怪しい点があれば指摘してほしい。動画で誤りを広めないように。
- US2：オーナーとして、台本を読んで直したら、映像と音声のタイミングを手で合わせずに済ませたい。
- US3：オーナーとして、できた動画を見て気になる箇所を言葉で指示し、直させたい。
- US4：オーナーとして、クリップを重ねるほど部品が増え、次の 1 本が速く、安定した品質で作れるようにしたい。
- US5：視聴者として、音を出さなくても字幕と図だけで内容がわかるようにしたい。

## 5. 機能要件
| ID | 要件 | MVP |
|---|---|---|
| F0 | 学習メモを受け取り、「伝えたい一点」と見せ方を決めて topic.md を生成する。論点が複数あれば 1 つを選び、残りは候補として記録する | ✓ |
| F1 | メモの主張を裏取りし、出典付きの調査メモを生成する。メモとの食い違いは明記する | ✓ |
| F2 | 調査メモから 60 秒用の台本（フック→本題→オチ）を生成できる | ✓ |
| F3 | 台本を「ビート」（ナレーション1文 ↔ アニメーション1動作）に分割できる | ✓ |
| F4 | ビートごとに TTS 音声を生成し、その長さで映像の尺を自動決定できる | ✓ |
| F5 | 専門用語の読みを辞書で指定できる（例：B+木 → ビープラスぎ） | ✓ |
| F6 | 再利用可能な CS 図解コンポーネントを持つ | ✓（001 に必要な分のみ） |
| F7 | 3b1b 風のモーション（描画・変形・移動・強調）を共通 API で提供する | ✓（最小セット） |
| F8 | 字幕を台本から自動生成し、音声と同期する | ✓ |
| F9 | Remotion Studio でプレビューし、MP4 を書き出せる | ✓ |
| F10 | 書き出し前に検証できる（尺・文字数・未定義ビート参照など） | ✓ |
| F11 | メモから MP4 までを 1 つの入口（Claude Code のスキル `/make-video <メモ>`）で一気通貫に実行する | ✓ |
| F12 | 映像を自己検証する：主要フレームを静止画に書き出し、Claude 自身が見て、はみ出し・重なり・読めない文字を直す | ✓ |
| F13 | 途中で止めて人がレビューできるモード（論点・台本の確認後に続行） | ✓ |
| F14 | 動画化しなかった論点を候補として蓄積する（backlog） | |
| F15 | TTS エンジンを AivisSpeech に切り替えられる | |
| F16 | 動画の補足テキスト（要点・出典・TTS クレジット）を生成する | |

## 6. 非機能要件
- **自動化**：既定では人の操作なしにメモから MP4 まで進む。人のレビューは任意で差し込める
- **正確性**：技術的事実には出典を付ける。裏取りで確証が得られない主張は台本に使わない
- **再現性**：クリップの全成果物をテキスト / コードで管理し、再レンダリングで同じ動画になる（git 管理）
- **量産性**：2 本目以降は「メモを置く → 実行 → 見る」で完結する
- **一貫性**：配色・フォント・イージング・テンポはテーマで一元管理する
- **可読性**：Shorts の UI に被らないセーフエリア内に情報を収める。スマホで読める文字サイズを保つ
- **ローカル完結**：TTS とレンダリングはローカルで動き、外部の有料 API に依存しない
- **ライセンス**：TTS キャラ / モデルの利用規約に従いクレジットを表記する

## 7. 制約・前提
- 実行環境：Arch Linux、Node.js 26、ffmpeg、Docker、Nix（direnv）
- 現状 npm が未導入 → Nix flake + direnv で用意する（決定済み Q1）
- VOICEVOX Engine は Docker（`factory/docker-compose.yml`）で起動する（決定済み Q2）
- Remotion は個人利用なら無料ライセンスで利用可能

## 8. MVP の定義
**DB インデックスに関する学習メモ 1 つから、`/make-video` 1 回でクリップ 001「インデックスはなぜ速い？」の MP4 ができること。**

### 受け入れ基準
- [ ] `clip/001-db-index/memo.md` を置いて `/make-video clip/001-db-index` を実行すると、途中で人の操作なしに `clip/001-db-index/out/video.mp4` まで生成される
- [ ] `clip/001-db-index/` に clip.yaml / memo / topic / research / script / beats / Scene が揃っている
- [ ] research.md の主要な主張すべてに出典が付いている
- [ ] コマンド1つで TTS 生成 → timing.json が更新され、映像が自動で追従する
- [ ] 書き出した MP4 が 1080×1920・30fps・60 秒以下である
- [ ] 字幕と図がセーフエリア内に収まり、スマホ実機で読める
- [ ] 音声のラウドネスが規定値（仕様書参照）に収まっている
- [ ] 台本の一文を修正して再生成しても、手作業でタイミングを直さずに済む
- [ ] レビューモードで実行すると、論点と台本の確認で一時停止し、承認後に続行できる

## 9. 対象外
- YouTube との連携全般（自動投稿、タイトル・説明文・ハッシュタグの生成、分析）
- BGM・効果音【要決定 Q5】
- 横長動画・長尺動画
